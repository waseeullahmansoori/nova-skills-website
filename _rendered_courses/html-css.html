Module 01 Web Foundations & Semantic HTML 5 Lessons ⌄
Module Focus: Understand web architecture, set up a professional VS Code development environment, write semantic HTML5 documents, and build accessible, multi-section web structures.
  • Master the mental model of client-server web architecture, domain names, hosting, and HTTP/HTTPS protocols.
  • Set up and configure VS Code with essential web developer tools, workspace settings, and clean folder structures.
  • Write standard-compliant HTML5 documents with valid doctype, language attributes, and metadata.
  • Structure content logically using heading hierarchies (H1–H6), paragraphs, semantic text formatting, and lists.
  • Incorporate hyperlinked navigation, relative and absolute paths, accessible images, and tabular data tables.
  • Implement HTML5 semantic landmarks (<header>, <nav>, <main>, <section>, <article>, <aside>, <footer>) instead of generic <div> containers.
  • Build accessible native HTML forms with associated labels, validation attributes, and keyboard operability.

Taught: Internet vs World Wide Web, browser rendering mechanics, client-server models, domain names, DNS, web hosting, HTTP/HTTPS, URLs, and static vs dynamic web pages.
  • How the internet works: packets, IP addresses, and domain name servers (DNS)
  • Client-server interaction: request-response cycles and HTTP status codes
  • Differences between static HTML/CSS sites and dynamic server-rendered applications
  • The distinct responsibilities of HTML (structure), CSS (presentation), and JavaScript (behavior)

Why It Matters: A clear mental model of how browsers load and display web pages prevents fundamental misconceptions about code execution and asset hosting.

Taught: Semantic headings (H1–H6), paragraphs, inline formatting tags, ordered and unordered lists, anchor tags, and internal/external linking strategies.

Taught: Images (<img>), descriptive vs decorative alt text, <figure> and <figcaption>, tables for tabular data, and HTML5 landmark containers.
  • Image integration: src paths, width/height dimensions, and format considerations (SVG, WebP, PNG, JPG)
  • Writing informative alt text for content images vs empty alt="" for purely decorative graphics
  • Editorial images with captions using <figure> and <figcaption>
  • Tabular data structure: <table>, <thead>, <tbody>, <tr>, <th> with scope attribute, and <td>
  • HTML5 landmark elements: <header>, <nav>, <main>, <section>, <article>, <aside>, and <footer>
  • Evaluating semantic tags vs generic <div> containers to avoid 'div soup'

Why It Matters: Appropriate semantic landmarks establish meaningful screen-reader regions and improve technical SEO ranking without extra styling code.
Expected Deliverable: An accessible, semantic HTML document featuring structured landmarks, captioned images, and a clean data table.

  • Input types: text, email, tel, number, url, password, date, checkbox, and radio groups

Taught: The CSS box model layers, content-box vs border-box, width, height, min/max dimensions, margin collapsing, display modes, and overflow handling.

  • position: relative: self-offsetting and establishing positioning contexts for child elements
  • position: absolute: anchoring elements relative to the nearest positioned ancestor

  • Understanding z-index layering and diagnosing stacking context traps

Module 03 Modern Responsive Layouts 5 Lessons ⌄
Module Focus: THIS IS THE CORE TECHNICAL MODULE. Master mobile-first design, fluid relative units, CSS Flexbox (1D), CSS Grid (2D), media queries, container queries, responsive images, and viewport stress testing.
  • Adopt a strict mobile-first responsive design methodology using fluid relative units (rem, em, %, vw, vh, clamp()).
  • Master CSS Flexbox for one-dimensional layouts: flex directions, axis alignments, wrapping, gaps, and flexible item sizing.
  • Master CSS Grid for two-dimensional layouts: explicit/implicit tracks, fractional fr units, repeat(), minmax(), and auto-fit/auto-fill.
  • Implement mobile-first media queries targeting content-driven breakpoints rather than arbitrary device widths.
  • Implement modern CSS container queries (@container) to create self-responsive components that adapt to their container width.
  • Deliver responsive images using max-width: 100%, object-fit, srcset, sizes, and <picture> elements.
  • Test and debug layouts across 5 representative viewports (320px, 390px, 768px, 1024px, 1440px) ensuring zero horizontal scrollbar bugs.
Key Concepts: Mobile-First PhilosophyRelative Units & clamp()CSS Flexbox (1D)CSS Grid (2D)Media QueriesCSS Container QueriesResponsive ImagesViewport QA (320px–1440px)
3.1 Responsive Principles, Mobile-First & Relative Units
Taught: Responsive web design foundations, viewport meta tag, mobile-first vs desktop-first philosophy, relative sizing units (rem, em, %, vw, vh, dvh), and fluid clamp() typography.
  • Why fixed-pixel desktop layouts fail on modern multi-screen devices
  • The viewport meta tag and its role in preventing mobile browser zoom emulation
  • Mobile-first development: establishing small-screen baseline CSS and progressively enhancing with min-width queries
  • Relative units: why rem is preferred for typography and spacing, em for component-relative scaling, and % for fluid widths
  • Modern viewport units: vw, vh, vmin, vmax, and dynamic dvh/svh to handle mobile browser address bars
  • Fluid typography and spacing formulas using clamp(min, preferred, max)
Learner Lab: Calculates and implements fluid typography and spacing scales that scale smoothly between 320px and 1440px without abrupt jumps.
Why It Matters: Mobile-first development ensures smaller mobile devices download only necessary styles and render fast, clean interfaces.
Expected Deliverable: A fluid layout foundation where font sizes and container padding scale proportionally across all viewport widths.
3.2 CSS Flexbox: One-Dimensional Layout Architecture
Taught: Flexbox layout engine, main and cross axes, flex container properties, item alignment, multi-line wrapping, gap spacing, and flexible item sizing.
  • Initializing flex containers: display: flex and display: inline-flex
  • Understanding main axis vs cross axis orientation with flex-direction (row, column, row-reverse, column-reverse)
  • Aligning items along the main axis using justify-content (flex-start, center, space-between, space-around, space-evenly)
  • Aligning items along the cross axis using align-items and per-item align-self overrides
  • Enabling multi-line wrapping with flex-wrap: wrap and spacing items using gap, row-gap, and column-gap
  • Controlling item growth and shrinkage: flex-grow, flex-shrink, flex-basis, and the flex shorthand
  • Building responsive navigation bars, centered hero callouts, and aligned button rows

Why It Matters: Flexbox is the definitive modern standard for 1D component layouts, replacing fragile floats and inline-block hacks.

3.3 CSS Grid: Two-Dimensional Page Layouts
Taught: CSS Grid architecture, grid tracks, columns, rows, fractional fr units, repeat(), minmax(), auto-fit, auto-fill, grid gaps, and explicit item placement.
  • Initializing grid containers: display: grid and grid-template-columns / grid-template-rows
  • The fractional unit (fr) and how it distributes available free space proportionally
  • Dynamic track generation using repeat() and flexible sizing bounds with minmax(min, max)
  • Building auto-responsive card grids without media queries using repeat(auto-fit, minmax(280px, 1fr))
  • Spacing grid cells cleanly using the modern gap property
  • Explicit item placement across grid lines using grid-column and grid-row spanning
  • Knowing when to use Flexbox (1D content flow) versus CSS Grid (2D structured page layouts)
Learner Lab: Constructs an auto-responsive product/service card gallery that automatically reflows from 1 column on mobile to 4 columns on widescreen.
Why It Matters: CSS Grid provides native two-dimensional layout power that makes complex card galleries and multi-column web pages trivial to build.

3.4 Media Queries, Breakpoints & Content Adaptation
Taught: Media query syntax, mobile-first min-width query structures, content-driven breakpoint selection, avoiding device-specific traps, and layout reflow.
  • Media query syntax: @media (min-width: 48em) and @media (min-width: 64em) using relative units
  • Mobile-first breakpoint progression: base (mobile) -> min-width: 768px (tablet) -> min-width: 1024px (desktop)
  • Content-driven breakpoints: introducing a media query when content naturally breaks, not because an iPhone has that width
  • Restructuring page sections across breakpoints: converting stacked mobile stacks into side-by-side columns
  • Adapting navigation, header heights, and footer multi-column layouts across tablet and desktop viewports
  • Diagnosing and eliminating unintended horizontal scrollbars caused by oversized fixed widths
Learner Lab: Implements progressive media queries to reflow a multi-section landing page seamlessly across phone, tablet, and desktop viewports.
