AI Agents Fundamentals: Design, Tools & Safety is a foundational, practical certification course that teaches you how to design, prototype, and evaluate tool-using AI agents. Unlike ordinary chatbots that only generate conversational text, agents decompose tasks, select and execute permitted tools, access document-grounded knowledge, and perform multi-step workflows under strict human oversight and safety guardrails.

A traditional chatbot primarily communicates conversationally with a user, generating text based on pre-training and immediate prompt context. An AI agent uses a language model as a reasoning and decision engine to decompose user goals, select from permitted tools (such as database searches or API calls), observe tool results, and complete multi-step tasks within bounded operational guardrails.

Deterministic automations (like standard n8n workflows) follow predefined, hardcoded conditional paths (e.g. 'If email contains X, do Y'). An AI agent operates with bounded autonomy: the model evaluates incoming input dynamically and decides which tools to call, in what sequence, and with what arguments to achieve the user's objective, while respecting safety constraints.

Yes. Tool calling is a central pillar of the curriculum (Module 03). You will learn how models inspect tool names, descriptions, and JSON parameter schemas, select appropriate tools for specific sub-tasks, receive and interpret tool execution results, and handle tool errors or timeouts.

Function calling (or tool calling) is a model capability where an LLM detects when external tools are needed, pauses generation, and outputs structured JSON containing the function name and validated arguments. The host application executes the tool locally and returns the result to the model, ensuring external code execution remains under developer control.

We introduce the core architectural concepts of the Model Context Protocol (MCP): why the open standard exists, client/server relationships, tools vs resources vs prompts, tool discovery mechanisms, trust boundaries, and user permission models. Complex custom MCP server engineering is reserved for advanced tracks.

You will build, test, and document two complete, supervised agent prototypes: (1) a Tool-Using Business Information Assistant that answers inquiries with verified source attribution, and (2) a Safe Business Task-Routing Agent that chooses allowed tools and pauses for human approval before sensitive actions.

The portfolio consists of three concrete deliverables: (1) The Tool-Using Business Information Assistant, (2) The Safe Business Task-Routing Agent, and (3) The 15-Case Agent Evaluation & Safety Test Suite with full trace logs and 5-dimension rubric scores.

Human-in-the-loop (HITL) approval is a critical safety architecture where sensitive or consequential agent actions (such as sending customer emails, modifying database records, or initiating financial transactions) are paused before execution. The agent creates a staged action proposal, alerts a human reviewer, and only executes if valid approval is granted.

Yes, prompt-injection defense is a compulsory topic (Module 05). You will learn the difference between direct user prompt overrides and indirect prompt injections concealed within retrieved documents or third-party tool responses, and how to implement pre-execution permission checks and output sanitization.

Guardrails are layered programmatic safeguards that restrict agent behavior. They include input validation filters, role and instruction boundary constraints, tool-level permission checks (principle of least privilege), human approval checkpoints, and output schema validators. Guardrails significantly reduce risk but do not guarantee complete immunity.

Yes. Thorough empirical testing is a core learning outcome. You will learn how to create test datasets, assess agents against normal requests, evaluate ambiguous inputs, test tool selection traps, verify permission denials, and document failure recovery.

The 15-case evaluation dataset includes: 5 valid requests with expected responses, 3 incorrect or ambiguous tool-selection traps, 2 permission error and human approval tests, 3 prompt-injection attacks (direct, indirect in document, and inside tool responses), and 2 failure recovery tests (tool timeout and malformed response).
