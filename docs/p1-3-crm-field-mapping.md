## 2. Multi-Touch Attribution & Marketing Metadata Mapping

In addition to the 21 spreadsheet columns, the JSON payload transmitted to the CRM endpoint contains full multi-touch attribution and technical telemetry. These fields are parsed by Google Apps Script and stored in metadata logs or supplemental reporting sheets:

| Telemetry Field Key | Data Type | Extraction Source | Description / Purpose |
|---|---|---|---|
| `utmSource` | String | URL `utm_source` or first-touch session | Latest traffic source (e.g. `google`, `chatgpt.com`, `instagram`). |
| `utmMedium` | String | URL `utm_medium` or first-touch session | Latest traffic medium (e.g. `cpc`, `ai_chat`, `organic`). |
| `utmCampaign` | String | URL `utm_campaign` or first-touch session | Latest marketing campaign name. |
| `utmContent` | String | URL `utm_content` or first-touch session | Ad creative or call-to-action identifier. |
| `utmTerm` | String | URL `utm_term` or first-touch session | Search keyword or audience target. |
| `firstTouchSource` | String | Stored `novaskills_attribution_first` | First documented touchpoint source. |
| `firstTouchMedium` | String | Stored `novaskills_attribution_first` | First documented touchpoint medium. |
| `firstLandingPage` | String | Stored `novaskills_attribution_first` | First URL path visited by the student. |
| `firstTouchReferrer` | String | Stored `novaskills_attribution_first` | External referrer URL on first arrival. |
| `aiPlatform` | String | User-Agent & Referrer detection | Detected generative AI referral (e.g. `ChatGPT`, `Perplexity`, `Claude`, `Gemini`). |
| `pageUrl` | String | `window.location.href` | URL where submission occurred. |
| `referrer` | String | `document.referrer` | Page that referred the user to the current URL. |
| `sourceComponent` | String | Function argument / Form ID | Component name (e.g. `demo_modal`, `counselling_modal`, `homepage_inline_counselling`). |
| `browser` | String | Client detector | Browser family and version (e.g. `Chrome 120`). |

| `publicIP` | String | `api.ipify.org` | Public IP for geocoding and duplicate spam filtering. |

## 3. Backward Compatibility & Legacy Aliases

To maintain backward compatibility with external webhooks, legacy serverless functions, and email triggers, the payload maintains identical data across standard and legacy keys:

| Standard Canonical Key | Legacy Alias 1 | Legacy Alias 2 | Purpose |
|---|---|---|---|
| `phone` | `mobile` | — | Supports webhooks expecting `mobile` or `phone`. |
| `recommendedCourse` | `course` | `courseTitle` | Supports templates expecting `course`. |
| `preferredMode` | `learning_mode` | `preferredLearningMode` | Supports forms using `learning_mode`. |
| `notes` | `message` | — | Supports email notifications expecting `message`. |
| `formType` | `lead_type` | — | Maps `demo_booking` -> `free_demo`, `career_counselling` -> `free_consultation`, `admission_enquiry` -> `enrollment_enquiry`. |
| `leadSource` | `sourceComponent` | `submissionMethod` | Provides clear attribution across all pipeline listeners. |

## 4. Minor Safeguard / Kids Tech Flagging Specification

When a student or parent selects any program from the **Kids Tech Academy** (e.g. `young-coders`, `scratch-programming`, `kids-mastery`, `python-for-kids`, `ai-for-kids`, `robotics-basics`, `web-design-for-kids`):

1. `guardianConsentRequired` is strictly set to `true`.
2. `minorSafeguard` is strictly set to `true`.
3. The string `[Minor Safeguard: Guardian/Parental Consent Required]` is appended to the `notes` (Column 21) field if not already present.
4. Admissions counsellors are instructed by standard operating procedures to request parental confirmation before booking demo batches.
