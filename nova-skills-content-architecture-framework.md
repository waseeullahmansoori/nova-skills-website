## 4. Program Overview Standard
Every course page hero and overview must follow this exact copy structure:
- **Course Title**: Clear, industry-recognized name.
- **One-Line Positioning**: Precise value proposition (e.g. *"Enterprise Full Stack Software Engineering with AI-Assisted Workflows, Next.js App Router & Cloud DevOps"*).
- **Short Explanation**: 2-3 sentences defining the core transformation without hype.
- **Key Facts Card**: Level | Duration | Mode | Est. Learning Hours | Project Count | Capstone Status | AI Integration Level | Prerequisites.
- **'What You Will Be Able To Do'**: 4–6 bullet points beginning with action verbs (*Architect, Deploy, Optimize, Measure, Scale*).

## 5. 'Why Learn This Now' Standard
Required for Templates B & C in evolving industries. Explains the 2026/27 industry inflection point without fear-mongering:
- Current industry paradigm shift (e.g. cookie deprecation, LLM tool calling, generative video).
- Business demand and hiring trends (backed by LinkedIn/NASSCOM evidence).
- Why traditional legacy approaches are failing.

## 6. Target Audience Standard
Prevents student mismatch and enrollment churn:
- **Best For**: 3–4 explicit profiles (e.g. Junior developers wanting to master fullstack architectures; Agency marketers needing GEO and CAPI tracking).
- **Who Is This NOT For**: Explicit negative criteria (e.g. Not for learners seeking passive theory without daily coding; Not for beginners lacking basic HTML).

## 7. Prerequisites & System Requirements Framework
Formalizes the three prerequisite tiers across all courses:
- **Tier 1: REQUIRED**: Strict dependencies that must be satisfied before enrollment (e.g. JavaScript mastery before React; Prompt engineering before Agentic systems).
- **Tier 2: RECOMMENDED**: Knowledge that improves learning speed but is not mandatory.
- **Tier 3: NOT REQUIRED / OPEN ENTRY**: Explicit statement that course begins from zero.
- **System Requirements**: Minimum hardware (RAM, GPU), required software versions, and free tier cloud accounts.

## 8. Measurable Learning Outcomes Standard
All outcomes must be observable, measurable, and tied to production tasks using Bloom's Revised Taxonomy action verbs:
- *Plan, Architect, Configure, Develop, Test, Deploy, Audit, Optimize, Present, Deliver.*
- **Strict Rule**: Vague phrases like "Understand X" or "Get familiar with Y" are prohibited.

## 9. Learning Journey Progression Model
The standardized 7-stage learning journey:
```
Stage 1: FOUNDATION          -> Mental model, vocabulary & environment setup
Stage 2: CORE                -> Essential mechanics & standard operating procedures
Stage 3: PRACTICE            -> Guided exercises & progressive difficulty tasks
Stage 4: APPLICATION         -> Commercial business brief execution
Stage 5: ADVANCED            -> Performance optimization, security & edge cases
Stage 6: PORTFOLIO PROJECT   -> Independent unguided commercial build
Stage 7: CAPSTONE / DEFENSE  -> Integrated enterprise solution presentation
```

## 11. Lesson-Level Architecture (The 6-Step Loop)
Every individual lesson must follow the pedagogical sequence:
1. **Concept (5-10 min)**: The mental model and real-world reason.
2. **Demonstration (10-15 min)**: Mentor live screen walkthrough.
3. **Guided Practice (15-20 min)**: Student follows step-by-step alongside instructions.
4. **Independent Lab (20-30 min)**: Student builds a variation without prompts.
5. **Real-World Application**: How an agency or tech team handles this.
6. **Assessment & Knowledge Check**: Quick quiz or automated code check.

## 12. Hands-on Tech & Tool Ecosystem Framework
Classifies software stacks into three transparent categories:
- **Core Tools**: Industry mandatory production tools (e.g. Figma, Next.js, Google Ads, Blender).
- **Supporting Tools**: Workflow accelerators and utilities (e.g. Notion, Postman, Canva, Make.com).
- **Emerging Tools**: 2026/27 modern generative and edge technologies (e.g. Cursor, n8n, Claude MCP, Runway Gen-3).
- **Tool-to-Value Mapping**: Every tool card must state: *Why it is used, What you learn, What you build.*

## 13. Industry Workflow Framework
Teaching the end-to-end professional pipeline rather than disconnected software features:
```
Brief / Requirement -> Research -> Planning -> Execution -> QA & Testing -> Delivery -> Measurement -> Optimization -> Documentation -> Scaling
```

## 14. Business Use Case Framework
Connecting every technical task to a commercial profit, efficiency, or growth metric:
- **Business Problem Solved**: The operational failure the client or company is experiencing.
- **Real-World Scenario**: Specific context (e.g. D2C brand losing 60% ad spend on unoptimized checkout).
- **Typical Deliverables**: Exactly what changes hands between contractor and client.
- **Client Workflow**: Briefing, milestone reviews, change requests, final sign-off.

## 15. AI Integration Framework
Structured integration across five formal levels (NONE, LOW, MEDIUM, HIGH, CORE):
- **AI Assists With**: Brainstorming, drafting variants, debugging, code boilerplate, semantic research.
- **AI Automates**: Image masking, routine data cleaning, initial translation, test scaffolding.
- **AI CANNOT Replace**: Strategic judgment, brand voice, system architecture, human empathy, edge-case ethics.
- **Human Verification & QA**: Mandatory protocols to verify AI outputs for hallucination, licensing, and security.

## 17. The 5-Level Project Framework
Progressive project depth mapped to course tiers:
- **Level 1: Guided Exercise**: Single-concept lab with complete step-by-step guidance (Modules).
- **Level 2: Practical Project**: Multi-step standalone functional deliverable (Micro Certifications).
- **Level 3: Portfolio Project**: Client brief simulation with unguided problem solving (Specializations).
- **Level 4: Integrated Project**: Multi-tool cross-functional production deliverable (Professional Tracks).
- **Level 5: Comprehensive Capstone**: Enterprise-scale production build with public defense (Master Programs).

## 20. Reusable Skill Matrix Framework
